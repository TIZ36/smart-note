# Screenshots for the project README

The top-level README references PNGs in this directory. Drop captures
here with **exactly these filenames** and the README renders them
automatically.

Recommended capture settings:
- macOS: `⌘⇧4` then space-bar over the window for a clean window
  screenshot with a soft drop shadow.
- Target width 1600 px (Retina) — GitHub will downscale to ~720 px in
  the rendered README.
- Capture with the **light** theme (Settings → Light) so the imagery
  reads well in both GitHub light + dark mode.

| Filename | What to capture | Notes |
|---|---|---|
| `hero.png` | Note channel — full-width editor with a real markdown file open, multi-tab strip visible, left file tree visible, at least one bookmark badge on a file row, a few chunks of writing visible. | The "hero" — most important. Take time to make this one look great. |
| `notes.png` | Same Note channel but zoomed on the editor + tabs + tree. Show bookmark gutter markers if any. | Wider crop than hero is fine; the editor's typography should be readable. |
| `library.png` | Library → Docs tab → a doc selected → Pipeline status card + Runs card both visible. | This is the "watch the engine work" shot — ideally pick a moment when something is `running` so the green spinner reads. |
| `chunks.png` | Same doc → click **Chunks** tab. Show the chunk_embed table at top + enrichment overlay table below. | Mock data is fine if you don't have real chunks for that doc — just need the layout to read. |
| `graph.png` | Same doc → click **Graph** tab. Both the related-list AND the workspace 2-column graph should have data. | Requires having actually enriched + topo'd ≥ 2 docs. |
| `ask.png` | Stream channel (default home) → ask a question → retrieval chips + AI answer streaming (or completed). | Citation markers `[1]` `[2]` visible in the answer makes this shot pop. |
