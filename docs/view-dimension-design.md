# 维度视图设计（raw -> note）

更新时间：2026-04-08

## 背景

用户日常会把待办、工作笔记、需求详情混合粘贴到 `raw`。系统应把“输入无结构”转换为“输出按维度组织”。

## 目标

- 自动发现主题维度，而不是只按时间堆叠。
- 让常用维度可单独查看与维护。
- 全部内容可追溯到 `raw` 原片段。

## 默认维度

- `Todo`：待办事项与跟进任务
- `需求列表`：需求、变更、验收、上线相关
- `项目经验`：按项目聚合的经验、复盘、踩坑、最佳实践
- `其他`：兜底分类

## 文件组织

- 主文件：`note.md`
- 维度视图目录：`views/`
  - `views/todo.md`
  - `views/requirements.md`
  - `views/project-<slug>.md`
- 每条记录包含来源引用：`raw#片段ID` 或 `raw:line`

## 生成策略

1. 增量抽取：只处理新增 raw 片段。
2. 维度分类：规则优先 + 语义兜底。
3. 写入主文档：更新 `note.md` 对应维度章节。
4. 写入视图：同步更新 `views/*.md`。
5. 主题升级：当某主题频次达阈值（如 5 次）建议升为独立视图。

## 独立视图机制

- 用户可将任意主题设为“独立视图”。
- 独立视图支持：
  - 置顶
  - 单独搜索
  - 单独导出
- 取消独立后内容回归父维度，不丢历史。

## UI 建议（Apple 风格）

- 左侧：维度导航（Todo / 需求列表 / 项目经验 / 其他）
- 中间：当前维度时间线 + 分组卡片
- 右侧：来源与证据面板（可回跳 raw）
- 顶部：`设为独立视图` 开关 + `仅看本主题` 过滤

## MVP 验收

- 混合输入可稳定分类到默认维度。
- 至少支持 1 个用户自定义独立视图。
- 每条内容均可回溯到 raw 来源。
- 增量更新不重写历史结构。
