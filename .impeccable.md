## Design Context

### Users
SmartNote is consumed by a broad audience of knowledge workers — researchers, writers, builders — who want a personal knowledge base that quietly organizes their notes and powers AI agents (Claude Code, Cursor) with their own memory. The product surface is a mix of mid-frequency tools (Ingest & Builds, Cloud Console, Wiki Sources) and high-frequency surfaces (Search, Note editor). Users come from many backgrounds; we cannot assume technical literacy beyond "they install desktop apps."

### Brand Personality
**Calm.** Three words: *calm, considered, durable*. The product sits at the edge of the user's workflow — it should never demand attention. Information is dense but never loud. Surfaces feel like quality stationery, not a dashboard. Confidence comes from restraint, not from accent colors.

### Aesthetic Direction
- **Theme**: Default light is warm-paper neutral (`oklch(~0.97 0.005 80)` family, hex `#faf9f7`). Dark is cool-blue OKLCH. A niho terminal-green theme exists for power users. Already-tinted neutrals throughout — keep that.
- **Color discipline**: 60–30–10. Almost everything is a neutral; the single accent (`--color-accent`, blue at oklch(0.65 0.15 250)) is rare and meaningful. Status colors (success/danger/warning) appear only on state, never on chrome.
- **Type**: System font stack at 13px base. No webfont loading — match the OS so it disappears. Hierarchy through weight + spacing, not through size jumps.
- **Spatial**: 4-multiple spacing (4/8/12/16/24). Asymmetric where it earns information density. Nothing centered for centering's sake.
- **Surfaces**: Subtle tint differences between bg-primary / bg-elevated / bg-surface. No drop shadows, no glassmorphism, no gradient text, no left-border accent stripes.
- **Motion**: Reserved. ease-out for state changes, 150–220ms. Respects reduced motion. No bouncy easing.

### Anti-References
- **Not Notion**: no emoji-as-icon, no playful empty states, no template gallery flavor
- **Not Linear**: not hyper-dense monospace dev-tool aesthetic; we serve broader users
- **Not Vercel/AI dashboards**: no neon cyan-on-black, no purple→blue gradients, no glow shadows
- **Not Stripe marketing**: no gradient hero numbers, no big colorful illustrations
- **Not "AI app" tells**: no rounded-rectangle icons-above-headings, no left-border accent stripes, no sparkline decoration

### Design Principles
1. **Quiet by default**. The interface should be the page the writing sits on, not a hero. Status, progress, and confirmation all whisper.
2. **Earn every accent**. The blue accent appears only when the user must act or has acted. Color = meaning.
3. **Density without pressure**. Information-rich layouts are fine; tightness must come from rhythm and alignment, not from cramming.
4. **No theatrical motion**. Transitions exist to communicate state change. They never decorate.
5. **System over style**. Use existing `proto-*` tokens and components. Polish tightens the system, never forks it.
